# PPT 제작용 프롬프트 (중간발표 10/16)

아래 구분선 안쪽 전체를 슬라이드 생성 도구(ChatGPT·Claude·Gamma 등)에 그대로 붙여 넣는다.
팀 템플릿을 쓸 경우 "디자인 지침" 절만 템플릿 규칙으로 바꿔라.

---

너는 대학 캡스톤 중간발표 슬라이드를 만드는 프레젠테이션 디자이너다. 아래 명세대로
**10분 발표용 본편 10장 + 백업 4장**의 슬라이드를 만들어라. 각 슬라이드마다
①제목 ②본문(핵심 문구·숫자) ③비주얼 지시 ④발표자 노트(실제로 말할 멘트, 한국어 구어체) ⑤목표 체류 시간을 출력하라.

## 절대 규칙

- **아래 "확정 수치" 외의 숫자를 새로 만들지 마라.** 수치가 필요한데 없으면 숫자 없이 문장으로 써라.
- 한 슬라이드에 메시지는 하나. 큰 숫자는 슬라이드당 1~3개만, 본문 글머리표는 3줄 이내.
- 표는 본편에서 최대 2장(성능 표, 로드맵)에만. 나머지는 문장·숫자·도식으로.
- 과장 금지. 명세에 "한계"로 적힌 내용은 숨기지 말고 해당 슬라이드에 그대로 노출하라.
- 16:9, 한국어.

## 맥락

- 프로젝트: **PC Crash Analyzer** — 원인 모를 PC 크래시(튕김·프리징·입력 누락·프레임 저하)의
  원인을 증거 기반으로 추론하는 진단 도구. 구조는 3단:
  **① 블랙박스 수집기**(상시 저부하 수집, 메모리 링버퍼, 크래시 자동 감지 시 전후 구간만 덤프, C#)
  → **② 추론 엔진**(층 판정 SW/드라이버/HW, 원인 후보 순위+근거, 최소 비용 점검 순서, C++)
  → **③ 안내 UI + 상담 에이전트**(판단은 엔진, 설명은 LLM, 조치는 사용자 동의 후에만).
- 1차 범위: **보안 프로그램 충돌** (안티치트·백신·금융 보안모듈).
- 청중: 이런 크래시를 겪어본 적 없는 지도교수. **발표 목표는 기능 자랑이 아니라
  "이 문제가 실재하고 흔하며, 기존 방법으론 안 되고, 우리 접근이 유효하다"는 설득.**
- 발표 시간 10분. 중간발표이며 최종까지 7주 남음.
- 팀: 7조 — 수집기·에이전트 담당 정태웅, 엔진·UI 담당 송민석, 사례 DB·실험 담당 남건호. (역할 표기는 이 이름 그대로)

## 확정 수치 (이 숫자만 사용)

[자체 설문 — 구글 폼, n=12, 2026-09-13~16. 반드시 "n=12, 초기 경향"을 각주로 표기]
- 타 프로그램(백신·보안 등)이 오류 원인이었던 경험: **83%**
- 원인을 정확히 찾은 사람: **50%** (추정만 42%, 끝내 못 찾음 8%)
- 시도한 해결책이 효과 없었다: **25%**
- "완전 자동 삭제·조치" 원함: **0%** / "확인 후 동의하면 실행": **92%** / "안내만": 8%
- 진단을 믿기 위한 요건 1위 "판단 근거 제시": **83%**, "신뢰도 % 표시": 58%
- 도구 사용 의향(5점 중 4~5점): **50%**
- 증상 경험: 튕김 67%, 프리징 42%, 실행 불가 42%, 입력 누락 42%, 블루스크린 25%
- 1차 대응: 인터넷 검색 75%, 재부팅 50%, AI에게 문의 42%
- 설문 원문 인용(따옴표 그대로 사용 가능):
  "PC는 오류 코드가 뜨지 않아 정확한 원인 파악이 어려움" / "검색해도 같은 증상이 나오지 않음" /
  "회사 백신·보안 프로그램은 임의로 지울 수 없음"

[테스트 PC 1대 실측 — 2026-10월, "PC 1대 실측" 각주 표기]
- 평범한 PC 1대의 7일치 로그: 크래시 보고(WER) 17건, 앱 크래시 4건, 비정상 종료(Kernel-Power 41) 1건
- 30일 안정성 기록 104건 (앱 오류 9, 응답 없음 3)
- 보안센터에는 백신 1개만 보이지만 커널에는 금융보안 드라이버 **8종+** 상주, 측정 중 안티치트 드라이버가
  아침엔 없다가 저녁에 등장
- 수집기 상시 부하: 30분 실측 CPU 평균 **0.13%**(머신 전체), 메모리 링버퍼 **~2.1MB** 상한, 게임 중 영향 없음
- 크래시 자동 감지: **18/18** (더미 크래시 3유형×3회×2라운드), 크래시→감지 **70~122ms**
- 수명 **90ms**짜리 프로세스의 로드 DLL 목록 확보 3/3 (ETW 실시간 추적)
- 수집 덤프 → 엔진 진단 연결(E2E) 동작 확인: 층 판정 SW 74%, 신뢰도 97% 출력
- 엔진 테스트 144/144 통과. 시나리오 6건(자작) 기준 점검 소요: 커뮤니티 표준 순서 103.7분 → 엔진 13.5분
  (**팀 추정 비용 기반 동작 확인 수준**임을 반드시 병기)

## 슬라이드 명세 (본편 10장)

1. **타이틀** (0:15) — 프로젝트명, 한 줄 정의("원인 모를 크래시의 블랙박스와 증거 기반 진단"), 팀 7조+역할.
2. **훅: 평범한 PC 한 대의 한 달** (0:45) — 실측 수치 3개(7일간 크래시 보고 17건 / 비정상 종료 1건 /
   보이지 않는 보안 드라이버 8종). 노트: "교수님 PC도 다르지 않습니다. 아무도 기록하지 않았을 뿐입니다."
3. **문제의 보편성 (설문①)** (1:00) — 큰 숫자 83%(보안SW가 원인이었던 경험)와 50%(원인 규명 성공률).
4. **사용자가 원하는 방식 (설문②)** (0:45) — 0% vs 92% 대비 비주얼. 노트: "완전 자동을 원한 사람은
   한 명도 없었습니다. 저희 설계 원칙과 일치합니다."
5. **기존 방법이 실패하는 이유** (0:45) — 설문 원문 인용 3개. 결론 문장: "증거가 남지 않는데
   검색·재부팅·AI 문의로는 풀 수 없다."
6. **해법: 3단 구조** (1:30) — 블랙박스→엔진→UI 도식. 각 단의 한 줄 역할 + 설계 원칙 3개
   (항상 기록하되 디스크엔 안 쓴다 / 판단엔 근거를 붙인다 / 조치는 동의 후에만).
7. **데모 (녹화 90초)** (2:00) — 슬라이드는 "크래시 → 90ms 감지 → 30초 후 덤프 → 근거 있는 진단"
   4단계 표시만. 노트: 영상 재생 중 라이브 해설 멘트 (크래시 순간, 감지 로그, 진단 화면의 근거·점검 순서 짚기).
8. **실측 성능** (1:00) — 표 1개: 상시 CPU 0.13% / 버퍼 2.1MB 상한 / 감지 18/18, 70~122ms /
   90ms 수명 프로세스 모듈 확보 / E2E 진단 동작·엔진 테스트 144/144.
9. **한계와 7주 계획** (1:30) — 왼쪽 "지금의 한계": 설문 n=12·실측 PC 1대, 엔진 검증은 자작 시나리오 6건,
   CPU 센서 미지원(보안 구성 — 우회하지 않고 GPU로 전환), UI는 Python 시안.
   오른쪽 로드맵: W1~2 WPF UI 1차+실사례 수집 시작 / W2~4 사례 20~30건 축적+보안SW 재현 실험 /
   W3~5 프레임 측정(PresentMon)+규칙 실측 갱신 / W5~6 WPF 2차+상담 에이전트 / W6~7 정확도 측정+통합.
   노트: "정확도 숫자는 사례가 모인 최종발표 때 가져오겠습니다."
10. **클로징** (0:30) — 한 문장: "크래시는 사라지지 않습니다. 저희는 그 순간을 기록하고, 근거로 설명하고,
    사용자의 동의 아래 해결합니다." + "지금 이 노트북에서도 수집기가 돌고 있습니다. 원하시면 바로 보여드리겠습니다."

## 백업 슬라이드 (Q&A용 4장)

B1. **n=12로 무엇을 주장하나** — 수요 규모가 아니라 설계 방향 검증(92% 동의-후-실행, 83% 근거 요구)에 사용.
    규모 근거는 실사례 수집(7주 계획)으로.
B2. **이벤트 뷰어·안정성 모니터와의 차이** — 그것들은 흩어진 '결과 로그'. 우리는 크래시 시점 전후의
    프로세스·DLL·드라이버·센서를 한 덤프로 묶고, 그 위에서 후보·근거·점검 순서까지 계산.
B3. **보안 프로그램이 이 도구를 차단하면?** — 실제로 겪음: 백신이 센서 드라이버를 차단 → 우회하지 않고
    GPU 센서로 전환. "보안을 거스르지 않는 진단"이 설계 원칙.
B4. **개인정보** — 파일 경로의 사용자명은 덤프 시 치환, 패킷 내용·키 입력은 수집하지 않음. 수집기는 읽기 전용.

## 디자인 지침

- 신뢰감 있는 딥네이비/차콜 + 포인트 1색. 장식 최소, 숫자가 주인공.
- 큰 숫자 슬라이드(3·4번)는 숫자 120pt 이상, 설명은 한 줄.
- 각주(n=12·PC 1대 실측)는 작게라도 반드시 해당 슬라이드에.
- 아이콘·일러스트는 추상적인 것만 (실존 보안 제품 로고 사용 금지).
