# 보안 프로그램 × 인터넷 사용 × 작업 프로그램 — 영향 실험 설계 (2026-11-10, 조사 반영 v2)

상위 계획: `conflict-test-plan.md`(M3 필터·검사 메커니즘). 근거 자료: `korea-ksa-research.md`(논문·뉴스·정책·측정 방법), `external-survey.md`(충돌 사례, 7절 취약점).

## 0. 요약

한국 금융 보안 프로그램이 깔린 PC에서 유튜브·은행·자료 검색을 하며 Blender·Godot·Notepad++를 쓸 때 얼마나 느려지고, 무엇이 충돌하고, 어떤 공격 면이 열리는지 측정한다.

- **사람이 직접 조작하지 않는다.** 사용자는 로그인과 시작 명령만 한다.
- 모든 조작·측정·판정 기준은 스크립트와 이 문서에 미리 고정한다.
- 조사한 범위에서 이 프로그램들의 성능 영향을 통제 실험으로 잰 자료는 없었다(`korea-ksa-research.md` 0절).

## 2. 신뢰성 원칙

1. **사람 손 0.** 조작은 스크립트가 한다. 사람이 건드린 런은 `GetLastInputInfo` 로 감지해 제외한다. 런 시작 때마다 마우스는 (0,0)에 둔다(Microsoft CLR 성능 지침).
2. **사전 등록.** 지표·반복 수·판정·제외 규칙을 S0 시작 전에 이 문서에 고정한다. 바꾸면 바꾼 사실과 이유를 기록한다.
3. **부팅이 측정 단위다.** 같은 부팅 안의 런끼리는 서로 닮아서, 런 수만 늘리면 신뢰구간이 거짓으로 좁아진다. 신뢰구간은 **부팅별 평균**으로 계산한다(Kalibera & Jones 2013). AV-Comparatives도 매 실행 후 재부팅한다.
4. **같은 출발점.** 부팅마다 로그온 → 5분 대기 → 유휴 안정(낮은 우선순위 CPU·디스크 사용이 잦아든 시점, Microsoft 평가 도구 기준) 확인 후 시작한다.
5. **무작위 순서 + 워밍업 버림.** 셀 순서는 부팅마다 새로 섞고, 시드를 기록한다.
6. **교란 차단·기록.** 실험 기간에는 Windows 업데이트를 일시 중지한다(AV-Comparatives·AV-TEST와 같다). Defender 검사가 끼어든 런은 제외한다. 부팅마다 환경 지문(OS 빌드·UBR, Chrome·GPU 드라이버·NVIDIA App·Defender 버전, HVCI)을 기록한다.
7. **조작 확인.** B2 런마다 보안 모듈 프로세스·포트가 실제로 떠 있었는지 기록한다. 깨어나지 않은 런은 B2로 치지 않는다.
8. **원자료 보존.** 런마다 즉시 파일로 남긴다. 중단돼도 이어서 할 수 있고, 분석은 원자료만으로 다시 돌릴 수 있게 한다.

## 3. 실험 설계

### 3.1 요인

| 요인 | 수준 | 바꾸는 비용 |
|---|---|---|
| **S** 보안 상태 | S0 없음(지금) · S1 은행 보안 10종 설치 · S2 구라제거기로 제거한 뒤 | 큼 — 설치·제거 |
| **B** 배경 인터넷 | B0 없음 · B1 유튜브 · B2 은행 로그인 페이지(모듈 활성) · B3 자료 검색 | 작음 — 런 단위 |
| **A** 전경 작업 | A1 Blender · A2 Godot · A3 Notepad++ | 작음 — 런 단위 |

- **주 셀**은 A × {B0, B2}의 6개다. 주 가설에 쓰고, 부팅마다 더 많이 반복한다.
- **보조 셀**은 A × {B1, B3}의 6개다.
- S0에서 B2는 은행 페이지가 "보안 프로그램 설치" 안내로 넘어간다. 그게 S0 사용자가 실제로 겪는 상태이므로 그대로 둔다.

### 3.2 순서 (바꿀 수 없음)

```
시범 3부팅 ─→ k 확정·문서 고정 ─→ S0 k부팅 ─→ 설치(morning-elevated.ps1, 통제 측정 70분)
  ─→ 적응 재부팅 2회(버림) ─→ S1 k부팅 ─→ 구라제거기 ─→ 재부팅 ─→ S2(증거 + 통제 측정)
```

- **S0은 설치 전에만 잴 수 있고, 나중에 늘릴 수도 없다.** 제거해도 드라이버·인증서가 남을 수 있어 S0으로 돌아갈 수 없다. 그래서 S0 부팅 수 k는 시범으로 넉넉히 정한 뒤 시작한다.
- **적응 재부팅**: 설치 직후 첫 부팅들은 드라이버 초기화, 첫 실행 작업, prefetch 재학습이 섞인다. Microsoft 평가 도구도 측정 전에 재부팅으로 학습시킨다.
- **S2**: 성능 블록 대신 `conflict-evidence.ps1` + `perf-measure.ps1`(약 20분)로 잔여 드라이버·인증서·서비스를 기록한다.

### 3.3 부팅 하나 안에서

- 워밍업은 앱마다 1회(버림, 3런)다.
- 본 실행은 주 셀 6개 × r_주 회 + 보조 셀 6개 × r_보조 회를 무작위 순서로 한다. 시범 전 잠정값은 r_주=3, r_보조=2로, 33런이다.
- 런 하나의 흐름:
  1. 배경 B를 연다.
  2. 30초 기다린다.
  3. 전경 작업 A를 실행하며 지표를 기록한다.
  4. 런 결과를 파일로 남긴다.
  5. 배경을 닫는다.
  6. 30초 쉰다.
  7. 오염 여부를 검사한다.
- 부팅 끝에는 `conflict-evidence.ps1`(B2 런 직후 상태)을 실행하고 수집기에 마킹한다.

### 3.4 시간 내역과 이유

**런 1회 ≈ 2.7분**

| 구간 | 시간 | 이유 |
|---|---|---|
| 배경 열기 + 안정 | 30초 | 브라우저 시작·페이지 로드·모듈이 깨어나는 순간 부하를 빼고 "켜 둔 상태"를 재기 위해 |
| 전경 작업 | 60~100초(추정, 스파이크에서 확정) | 앱 시작 + 작업 + (Notepad++) 500자 입력 |
| 기록·배경 닫기 | 10초 | 중단에 대비해 즉시 저장 |
| 휴지 | 30초 | 앞 런이 남긴 일(새 파일 검사, 캐시, 클럭·온도)이 다음 런에 섞이지 않게 |

**부팅 1회 ≈ 1.6시간** = 33런 × 2.7분 + 시작 대기·점검·끝 증거 약 10분

**전체 (k=4 잠정)**

| 단계 | 시간 | 빼면 잃는 것 |
|---|---|---|
| 시범 3부팅(워밍업 3 + 주 셀 × 2회 = 15런/부팅) | 약 2.5시간 | k·r 근거. 없으면 반복 수가 짐작이 된다 |
| S0 k=4부팅 | 약 6.4시간 | 기준. 부족해도 나중에 늘릴 수 없다 |
| 설치 + 통제 측정 + 적응 재부팅 2회 | 약 1.5시간 | 설치마다 바뀐 포트·드라이버·인증서, 모듈 자체 비용 |
| S1 k=4부팅 | 약 6.4시간 | 본 측정 |
| S2 | 약 0.5시간 | 잔여물 |
| **합계** | **약 17시간** | k=3이면 약 14시간 |

**왜 부팅을 여러 번 하나:** 부팅 평균 k개로 신뢰구간을 낼 때 t값은 k=2면 12.7, k=3이면 4.3, k=4면 3.2다. 신뢰구간 반폭은 t/√k에 비례하므로, 부팅 2번이면 같은 흔들림이라도 4번일 때보다 약 5.6배 넓다(8.98 대 1.59). 이전 v1 설계(상태당 2부팅 × 긴 블록)는 시간은 비슷하면서 이 점에서 약했다.

**빠른 판(선택):** 시범 없이 k=2, 주 셀만 하면 약 6시간이다. 큰 효과(대략 10% 이상)만 판단할 수 있고, S0을 나중에 늘릴 수 없다는 점은 같다.

**사용자 개입(11/10 결정: 없음):** 시작 전 한 번의 준비와 시작 명령 외에는 사람 손이 필요 없게 만든다. 실험 기간에만 Windows 자동 로그인을 쓰고(암호가 시스템에 저장되므로 끝나면 끈다), 단계 전환과 재부팅은 상태 기계가 한다. 11절.

### 4.3 배경 인터넷

- Chrome 전용 프로필(`--user-data-dir=lab\runs\profile`, 부팅마다 새로)로 연다.
  - 계정·확장 프로그램은 없다.
  - 플래그: `--no-first-run --no-default-browser-check --autoplay-policy=no-user-gesture-required --mute-audio`
- **페이지를 조작하지 않는다.** WebDriver·DOM 자동화를 쓰지 않고, 자동화 탐지를 피하는 장치도 쓰지 않는다.
- **로컬 네트워크 액세스(LNA):** Chrome 142+는 공개 사이트가 localhost 모듈에 붙을 때 권한을 요구한다. 차단되면 모듈이 연결되지 않는다(하나은행·KB국민은행 공지).
  - 실제 사용자는 "허용"을 누른다. 실험에서는 **전용 프로필에만** 은행 도메인 허용을 미리 넣거나, 은행이 안내하는 `local-network-access-check` 비활성화를 이 프로필의 실행 인자로 준다. 시스템 정책은 바꾸지 않는다.
  - 어느 방법이 되는지는 스파이크 11에서 확인한다.
  - 허용하지 않은 상태에서 모듈 연결이 실패하는 모습 자체도 S1에서 한 번 기록한다. 실제로 보고된 충돌 사례이기 때문이다.
- B1 유튜브: 고정 공개 영상 1개. 광고와 네트워크 변동은 잡음으로 보고, 수신 바이트를 기록한다.
- B2 은행: **아직 설치를 요구하는 은행** 중 2곳의 공개 로그인 페이지를 열어 둔다.
  - 2026-04 보도 기준 후보는 하나·신한·농협·수협·부산·경남·전북·광주·제주다.
  - 그중 우리 설치본 10종과 겹치는 모듈을 부르는 곳을 스파이크 12로 고른다.
  - **로그인·입력은 하지 않는다.** 블록당 페이지 로드 수에 상한을 둔다.
  - 정부가 2026년 말까지 전환을 지시했으므로 실험 중 무설치로 바뀔 수 있다. 조작 확인(2절 7)이 이를 잡는다.
- B3 자료 검색: 고정 URL 10개(위키백과, 공식 문서 등)를 20초 간격으로 돌아가며 연다.

### 4.4 측정 장치

- **샘플러:** 전체 CPU·DPC·인터럽트, 메모리, 디스크 처리량·지연, 네트워크, GPU 엔진을 기록한다. 감시 프로세스는 프로세스별로 기록한다.
  - 감시 대상: 보안 모듈(설치 diff로 확정, 후보는 `korea-ksa-research.md` 4절), 브라우저, 전경 앱, NVIDIA
  - 샘플러 자신의 부하도 기록한다.
- **UI 탐침:** 전경 앱 창에 100ms마다 `SendMessageTimeout(WM_NULL, SMTO_ABORTIFHUNG, 1000ms)` 을 보내 응답 시간을 잰다. Windows가 "응답 없음"을 판단하는 방식과 같은 원리다.
- **입력 지연, 범위를 정직하게:**
  - `SendInput` 은 하드웨어 입력 큐, 즉 커널 키보드 드라이버 스택 **다음**에 들어간다(Microsoft 문서·Raymond Chen).
  - 키보드 보안(nxKey 드라이버 훅, TouchEn Key)의 암호화 경로는 은행 페이지의 **보호된 입력칸에 초점이 있을 때** 동작한다.
  - 그래서 1단계의 Notepad++ 입력 지연은 **일반 간섭**(CPU 경쟁, 사용자 모드 훅)만 잰다.
  - 키보드 보안 경로 자체는 2단계에서 잰다. USB 키보드로 인식되는 마이크로컨트롤러 + 보호 입력칸 초점(은행 페이지 조작이 필요하므로 별도 결정).
- **증거:** `conflict-evidence.ps1` 을 부팅 끝, B2 런 직후 상태에서 실행한다.
- **수집기:** 콘솔 수집기를 로컬에서 실행하고 런마다 마킹한다. 트레이·업로드는 꺼 둔다.

## 6. 분석 (사전 등록)

- 런 값 → **부팅별 중앙값** → 상태(S0·S1)별로 부팅 값 k개를 모은다.
- 효과 = S1 평균 / S0 평균 − 1. 95% 신뢰구간은 부팅 값으로 t 분포(자유도는 부팅 수 기준)를 써서 구한다. 비율의 신뢰구간은 단일 평균보다 약 √2배 넓다는 점을 반영한다.
- **효과로 인정하는 조건(모두):** 신뢰구간이 0을 포함하지 않음 + 같은 방향이 주 셀 3개 앱 중 2개 이상.
- **검출 가능한 최소 효과(MDE)를 같이 보고한다.** 예를 들어 "이 설계로는 x% 미만 차이는 판단할 수 없다"고 쓴다. 참고로 일반 백신의 영향은 앱 실행 2~4%, 웹 로드 13~16% 수준으로 보고됐다(AV-TEST). 몇 % 수준은 놓칠 수 있다.
- **주 가설(미리 정함):** S1·B2에서 ① 세 앱의 시작 시간, ② UI 멈춤이 S0·B2보다 크다. 나머지 셀·지표는 탐색으로 보고, 숫자는 모두 공개한다.
- **k·r 결정(시범 후, S0 전에 고정):**
  - 부팅 간 분산 T²(부팅)과 부팅 내 분산 T²(런), 부팅·런 비용 c를 구한다.
  - r = ⌈√((c부팅/c런)·(T²런/T²부팅))⌉
  - k ≈ (t·부팅 평균의 변동계수 / 목표 반폭)², 목표 반폭은 5%로 둔다.
  - k는 최소 3, 최대 6이다.
- S2는 S0과 비교해 잔여물만 본다.
- RQ5: 각 런의 덤프에 `ground_truth.json`(`symptom: slow`, `cause_category: M3`, S1이면 `culprit` = 보안 모듈, S0이면 `null`, **`confidence: controlled`**)을 붙여 엔진을 평가한다. `controlled` 는 벤더 공식(`official`)과 섞지 않고 별도 행으로 보고한다.

## 7. 안전·윤리 규칙

- **게임에는 어떤 자동 입력도 보내지 않는다**(로스트아크는 매크로 사용 시 계정 정지). preflight는 게임·런처·안티치트 프로세스(LOSTARK, STOVE, Riot, EAC·BattlEye 게임 등 `lab.json` 목록)가 떠 있으면 시작을 거부한다. 안티치트 영향은 1단계에서 제외한다.
- 은행 사이트: 공개 로그인 페이지만 연다. 로그인·실제 정보 입력·자동화 탐지 우회는 하지 않는다. LNA 허용은 전용 테스트 프로필에만 둔다.
- 브라우저와 앱은 일반 권한으로 띄운다.
- 데이터는 로컬에만 둔다(`runs/` git 제외). PC 블랙박스 트레이와 업로드는 꺼 둔다.
- 설치 전 복원 지점을 만들고, 끝나면 구라제거기로 제거한다.
- 실험 기간에는 Windows 업데이트를 일시 중지한다. 자동 로그인을 쓰면 실험이 끝나는 즉시 끈다(사용자가 직접).

## 11. 완전 무인 실행 (11/10 추가)

목표: 사용자가 **한 번 준비하고 한 번 시작하면**, 시범 → k 결정 → 설치 전 측정 → 설치 → 적응 재부팅 → 설치 후 측정까지 사람 없이 끝난다. 약 이틀이 걸리고 그동안 PC를 쓸 수 없다.

### 11.1 상태 기계

```
lab\runs\state.json  ← 지금 어느 단계의 몇 번째 부팅인지, 끝난 런, 실패 횟수

로그온(자동 로그인) → [일반 권한 작업] lab\run-next.ps1
   ├ state 읽기 → 사전 점검 → 이번 부팅의 블록 실행 → state 갱신
   ├ 다음이 "설치" 단계면 → [관리자 작업]을 실행시키고 끝날 때까지 대기
   └ 남은 단계가 있으면 재부팅, 없으면 종료하고 결과 요약 화면
```

- **시범 뒤 k·r 결정도 코드가 한다.** 6절의 식을 그대로 구현하고, 계산값과 입력(분산·비용)을 기록한다. 사람이 숫자를 보고 고르지 않으므로 사전 등록 원칙에도 맞다. k는 3~6 범위로 자른다.
- 브라우저와 앱은 일반 권한 작업에서 띄운다. 관리자 작업은 설치와 관리자 전용 기록(미니필터 목록 등)만 한다.
- 관리자 작업은 사용자가 미리 "가장 높은 권한으로 실행"으로 등록해 둔 예약 작업이다. Windows 승인 창을 우회하는 것이 아니라, 등록할 때 한 번 승인받는 Windows의 정식 방법이다(PC 블랙박스 트레이의 자동 실행과 같은 방식).

### 11.3 설치 자동화는 미리 시험할 수 없다

이 PC에 한 번이라도 설치하면 "설치 전" 상태가 사라진다. Windows 11 Home이라 가상 머신이나 Windows 샌드박스로 미리 해 볼 수도 없다. 그래서 설치 창 4개의 자동화는 **본 실행에서 처음** 돌게 된다. 대응은 다음과 같다.

1. 실패해도 멈추지 않는다. 제한 시간이 지나면 건너뛰고 다음으로 간다(지금 스크립트가 이미 그렇게 동작한다).
2. 설치 뒤에 실제로 무엇이 깔렸는지 기록한다. 설치 후 측정은 "깔린 것만으로" 진행하고, 보고서에 10종 중 몇 종이었는지 적는다.
3. 가능하면 **다른 PC(팀원 PC나 여분 PC)에서 설치 자동화만 먼저 시험**한다. 그 PC는 측정 대상이 아니므로 설치 전 상태를 잃어도 된다. 이것이 가장 확실하다.
4. 설치 파일을 풀지 않고 볼 수 있는 정보(설치 도구 종류, 문자열)로 조용한 옵션 후보를 미리 찾는다.

### 11.4 멈춤과 사고 대비

- 블록이 연속 2번 실패하면 재부팅을 멈추고 상태 파일과 화면에 이유를 남긴다. 무한 재부팅을 막기 위해 전체 재부팅 횟수에도 상한을 둔다.
- 런마다 결과를 바로 저장하므로 정전·크래시 뒤에는 그 런부터 이어서 한다.
- 설치 후 부팅이 안 되는 경우에 대비해 설치 직전에 복원 지점을 만든다. 복원은 사람이 해야 한다.
- 실행 중에 사람이 키보드·마우스를 건드리면 그 런만 제외된다. 멈추려면 상태 파일에 정지 표시를 하는 명령 하나를 쓴다.

### 11.5 사용자가 하는 일 (전체)

**시작 전 한 번(약 10분, 관리자 권한 필요)**

1. 자동 로그인 켜기
2. 예약 작업 2개 등록(스크립트 하나로)
3. Windows 업데이트 일시 중지
4. PC 블랙박스 자동 실행 끄기
5. 게임·런처 종료
6. 시작 명령 실행

**끝난 뒤**

1. 자동 로그인 끄기
2. 결과 확인
3. 제거 단계: 구라제거기는 화면에서 직접 조작해야 한다. 측정이 모두 끝난 뒤의 일이라 "중간"은 아니다. 제품별 제거 프로그램으로 자동화할 수 있는지는 따로 확인한다.

자동 로그인을 켜고 끄는 일과 예약 작업 등록은 시스템 설정을 바꾸는 일이라 스크립트를 준비해 드리되 실행은 사용자가 한다.
