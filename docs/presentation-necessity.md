# 중간발표 설득 자료 — 왜 이 도구가 필요한가

> 청중 전제: 이런 크래시를 직접 겪어본 적 없는 평가자. "이게 진짜 문제인가? → 흔한 문제인가? →
> 기존 방법으론 왜 안 되나? → 너희 방식은 뭐가 다른가?" 순서로 설득한다.
> 수치 출처: ① 자체 설문(구글 폼, **n=12, 2026-09-13~16 — 초기 경향**으로 명시할 것) ② 테스트 PC 1대 실측
> (collector/NOTES.md, docs/collector-status.md) ③ 엔진 시나리오(engine/data/samples).

## 1. 문제는 실재하고, 흔하다

**설문 (n=12):**
- 원인 모를 오류 경험 증상: 튕김 67% · 프리징 42% · 실행 불가 42% · 입력 누락 42% · 프레임 저하 33% · 블루스크린 25%
- 원인을 정확히 찾은 사람은 **절반(50%)뿐** — 42%는 추정, 8%는 끝내 미해결
- **타 프로그램(백신·보안 등)이 원인이었던 경험 83%** — 가장 흔한 원인군
- 시도한 해결책이 "효과 없었다" 25% — 넷 중 하나는 셀프 트러블슈팅이 헛수고

**실측 (평범한 PC 1대, 2026-10월):** 설문이 과장이 아님을 보여주는 물증.
- 7일치 이벤트 로그만 뒤져도: WER 크래시 보고 17건, 앱 크래시 4건, **비정상 종료(Kernel-Power 41) 1건**
- 30일 안정성 기록 104건 (앱 오류 9, 응답 없음 3)
- 보안센터에는 Defender 하나만 등록돼 있지만, 커널에는 **금융보안 모듈 드라이버 8종+ 상주**
  (AhnLab Safe Transaction 5종, ImageSAFER, TouchEn, JRSUKD25) — 은행 한 번 쓰면 깔리고, 안 보이는 곳에 남는다
- 측정 중 안티치트 드라이버(Wellbia xhunter2.sys)가 **아침엔 없다가 저녁에 등장** — 게임 한 판이 커널 상주물을 바꾼다
- 테스트 도중 서드파티 앱 실제 크래시 1건이 자동 포착됨 (의도하지 않은 실전 검증)

**발표 화법 제안**: "저희 팀원 PC 한 대를 한 달 재봤더니 이랬습니다. 교수님 PC도 다르지 않습니다 —
다만 아무도 기록하지 않았을 뿐입니다."

## 2. 기존 방법이 안 되는 이유 (설문 D2 원문이 그대로 근거)

| 설문 응답 (원문) | 본질 |
|---|---|
| "PC는 오류 코드가 뜨지 않아 정확한 원인 파악이 어려움 (모바일과 대비)" | **증거 부재** — 크래시 순간의 상태가 아무 데도 안 남는다 |
| "어느 부분이 문제인지 몰라서 하나씩 바꿔보는 게 귀찮다" | **탐색 비용** — 무작위 이분탐색을 사람이 한다 |
| "검색해도 같은 증상이 안 나온다" | 증상은 같아도 **원인 조합이 PC마다 다름** |
| "회사 백신·보안 프로그램은 임의로 지울 수 없음" | 삭제가 아니라 **공존 진단**이 필요 |
| 인터넷 검색 75%·재부팅 50%가 1차 대응, AI 문의도 42% | 전부 **증거 없이 추측**에 의존 — AI도 입력이 없으면 못 푼다 |

## 3. 우리 설계가 설문 요구와 일치한다 (수요 검증)

| 설문이 요구한 것 | 우리 시스템 | 상태 |
|---|---|---|
| 진단을 믿으려면 "판단 근거 제시" **83%** (1위) | 엔진이 후보마다 근거 그래프 제시 ("문제 시점에 대상 프로세스에 로드돼 있었다" 등) | 구현·동작 확인 |
| "신뢰도 % 표시" 58% | 층 판정·후보별 신뢰도 % 출력 | 구현·동작 확인 |
| **완전 자동 조치 원함 0% / "확인 후 동의하면 실행" 92%** | 안내 모드 기본 + 자동 점검은 되돌릴 수 있는 조치만 동의 후 실행. 수집기는 원천적으로 읽기 전용 | 설계 원칙으로 고정 |
| 우려: "권한이 너무 강하면 걱정" "랜섬웨어·해킹툴 우려" (E6) | 실증 일화: 센서 드라이버가 Defender에 차단되자 **우회하지 않고 GPU 수집으로 전환** — 보안을 거스르지 않는 도구임을 보여주는 사례 | 실화 (NOTES 기록) |
| 도구 사용 의향 50%, 도움 체감 기대 3.83/5 | — | 수요 신호 |

**핵심 문장 후보**: "응답자의 92%는 '확인 후 동의하면 실행'을 원했고 완전 자동을 원한 사람은 0명이었습니다.
저희는 이 결과가 나오기 전부터 같은 원칙으로 설계했고, 설문이 그 방향을 확인해 줬습니다."

## 4. 직군별 시나리오 — "당신의 작업 도구도 해당된다"

설문 B3의 실제 사건들이 엔진 시나리오·실측 신호와 그대로 연결된다:

| 대상 직군·프로그램 | 전형적 충돌 | 설문 실사례 (B3) | 우리 쪽 대응물 |
|---|---|---|---|
| 게임·모드 | 커널 안티치트 ↔ 무관한 게임/모드 충돌 | "안티치트·보안프로그램 충돌로 클라이언트 크래시" | 엔진 s1 + 실측: xhunter2 상주 포착, 비시스템 주입 DLL 보유 프로세스 156개 |
| 사무·금융·회사 프로그램 | 금융보안·사내 보안 에이전트의 키보드 필터/후킹 | "게임 채팅 칠 때만 한 글자씩 씹힘" (입력 누락) | 엔진 s2 + 실측: 금융보안 드라이버 8종, UpperFilters·미니필터 수집 |
| 개발 (VSCode/PyCharm/빌드) | 백신 실시간 검사의 오탐·격리·I/O 간섭 | "Gromacs가 작동되지 않음", 설문 83% "백신·보안이 원인이었다" | 엔진 s3·s6 (오탐 격리, 후킹 DLL 크래시) |
| 영상·3D (프리미어/Maya/Blender/CAD) | GPU 드라이버 TDR, 과열 스로틀 | "맥북이 팬 소음 내며 느려짐" (발열) | 엔진 s4·s5·s7 + 실측: GPU 온도·클럭·TDP% 2초 수집, TDR(4101) 자동 마킹 |
| 공통 | 업데이트 직후 회귀 | "윈도우 업데이트로 커서 스킨 미적용" | 설치·업데이트 이력 수집 → 엔진 시간 상관 근거 |

전문자료·커뮤니티·실무자 인터뷰를 더할 때, 각 사례를 위 표의 행에 꽂으면 "산발적 일화"가 아니라
"같은 구조의 문제"로 묶여 보인다.

## 5. 효능 — 말이 아니라 측정값으로

| 주장 | 근거 수치 (실측) |
|---|---|
| 항상 켜 둬도 부담 없다 | 30분 실측 CPU 평균 0.13%(머신 전체), 링버퍼 ~2.1MB 상한, 게임 중 영향 없음 |
| 크래시를 놓치지 않는다 | 자동 감지 18/18 (CrashDummy a/b/c ×3, 두 라운드), 이벤트 지연 70~122ms |
| 죽은 프로세스의 증거를 남긴다 | 수명 90ms 프로세스의 로드 DLL 목록 확보 3/3 (관리자+ETW) — 기존 도구로 불가능한 지점 |
| 수집 → 진단이 실제로 이어진다 | 실측 덤프로 crash_engine 진단 동작 (층 판정 SW 74%·신뢰도 97%), 엔진 테스트 144/144 |
| 점검 순서가 시간을 줄인다 | 시나리오 6건 기준 커뮤니티 표준 순서 103.7분 → 엔진 13.5분 (팀 추정 비용 기반, 동작 확인 수준임을 명시) |

## 6. 솔직함이 설득력이다 — 한계 먼저 말하기

- 설문 n=12 (초기 경향), 실측 PC 1대 — "그래서 사례 20~30건 수집·제어 실험이 다음 단계"로 연결
- CPU 센서는 현 보안 구성에서 미지원 → GPU 기준 전환 (보안을 우회하지 않는다는 원칙의 대가이자 증거)
- 엔진 정확도 수치는 아직 자작 시나리오 6건 — "정확도가 아니라 동작 확인" (엔진 README 표현 그대로)
- 질문 대비: "n=12로 뭘 주장할 수 있나?" → 수요의 존재 증명이 아니라 **설계 방향 검증**(92% 동의-후-실행,
  83% 근거 요구)에 쓴다고 답하기. 규모 주장은 실측·외부 자료(커뮤니티·인터뷰) 몫.

### 발표 흐름 제안 (설득 목표 기준)

1. 훅: 실측 한 달 수치 ("평범한 PC 한 대에서…") — 문제의 실재
2. 설문: 83%가 보안SW발 오류 경험, 원인 규명은 절반뿐 — 문제의 보편성
3. D2 원문 인용: 왜 기존 방법(검색·재부팅·AI 문의)이 실패하는가 — 증거 부재
4. 해법 구조: 블랙박스(증거) → 엔진(근거 있는 추론) → 안내(동의 후 실행) — 설문 요구와 1:1
5. 라이브 시연: CrashDummy 크래시 → 30초 뒤 자동 덤프 → UI에서 진단·근거·점검 순서
6. 한계와 다음 단계 — 사례 DB 축적, WPF UI, PresentMon
