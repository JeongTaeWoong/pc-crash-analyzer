# ui/wpf/CrashAnalyzer.UI — 최종 UI (C# WPF) v1

Python 시안(`ui/prototype-python`)의 C# WPF 포팅 + **수집기 상주 통합** 1단계 (2026-10-12 결정 사항 이행).
UI는 판단하지 않는다 — 층·확률·순서·실행 방식은 전부 엔진(`crash_engine tool ...`)의 응답을 그대로 보여 준다.

## 빌드·실행

```powershell
# 선행: 엔진 빌드(engine/README.md), 수집기 빌드(dotnet build collector/BlackBox -c Release)
dotnet build ui/wpf/CrashAnalyzer.UI -c Release
ui\wpf\CrashAnalyzer.UI\bin\Release\net8.0-windows\CrashAnalyzerUI.exe
```

- 엔진 위치는 자동 탐색(`engine/build/Release/crash_engine.exe`), 다르면 `CE_ENGINE` 환경 변수.
- 덤프 탐색 루트는 `collector/` 전체, 다르면 `CE_DUMPS`.
- `--selftest [출력파일]` : GUI 없이 엔진 연결·진단 매핑 검증 (스모크/CI용).
- `--open <스냅샷.json>` : 시작하자마자 해당 스냅샷을 진단 (시연용).
- `--shot <저장.png> [--open ...]` : 창을 화면 밖에서 렌더해 PNG로 저장 후 종료 — 사용자 화면을
  캡처하지 않는 자가 검수용.

## 2026-11-02 추가 — 확정 시안 2-4 반영 (송민석)

팀에서 2026-10-30 에 확정한 UI 시안 **2-4**(블랙박스는 메인에서 빼고 별도 페이지, 상담은 버튼으로 여는 챗봇 창)에 맞춰
화면을 다시 짰다. Python 시안(`ui/prototype-python`, 2026-10-30 판)과 같은 구성·동작이다.
엔진 호출(`diagnose`, `session_*`, `explain`)과 수집기 상주 기능(시작/중지 · 로그 · 새 기록 자동 검진)은 그대로다.

| 페이지 / 영역 | 내용 |
|---|---|
| 머리글 | `PC 크래시 검진` · [검진 결과 \| 블랙박스 기록 ↗] 전환 · 수집기 상태(누르면 블랙박스 페이지) · 안내/자동 점검 모드 · [최근 기록 열기] [파일 열기…] |
| 단계 표시 | ① 진단 ② 원인 확인 ③ 해결 안내 ④ 검증 (세션 상태로 표시) |
| **검진 결과** 왼쪽 | 가장 유력한 원인(원형 그래프, 점검 결과가 반영된 확률) · 층별 상태 카드(주의/관찰/양호) · "아님: …"(그대로였던 점검) · 원인 후보 순위 막대(누르면 근거) · 점검 진행 목록 |
| **검진 결과** 오른쪽 | **지금 할 일**: 원인 확인 중에는 지금 할 점검 1개와 결과 버튼(+ "왜 이게 먼저예요?"), 원인이 확인되면 해결 방법·적용·검증 |
| 상담 도우미(챗봇) | 오른쪽 아래 **그림 버튼을 누르면 언제든 챗봇 창이 열린다**(두 페이지 모두). 닫아도 대화는 남는다. **점검을 다 해도 원인을 못 찾았을 때(`exhausted`)**, **해결책이 모두 실패했을 때(`failed`)**, **검증에서 재발했을 때**는 창이 저절로 열리고 버튼 옆 글자가 초록색 "문제가 남았어요 · 상담하기"로 바뀐다 |
| **블랙박스 기록** 페이지 | 같은 창 안에서 전환(별도 창 아님). 수집기 덤프 폴더의 `events.json`·`meta.json` 으로 앞 5분 ~ 뒤 30초를 가로 타임라인(오류 이벤트 / 프로그램 시작·종료 / 모듈 로드 / GPU 사용률 / GPU 온도, 빨간 줄 = 문제 순간)과 시간순 목록으로 보여 준다. 오른쪽에 "문제 순간에 실행 중이던 후보", "선택한 기록", **블랙박스 수집기**(시작/중지 · 자동 검진 · 최근 활동). 수집기 로그는 왼쪽 목록의 [수집기 로그] 탭 |

* 기록을 열면 바로 세션을 시작한다(예전의 [원인 확인 시작] 버튼 없음). 엔진 호출 순서: `diagnose` → `session_start`.
* 실험용 시나리오(`engine/data/samples`)처럼 수집기 원본 기록이 없으면 스냅샷의 `events`·`change_history` 만으로 타임라인을 그린다.
* 층별 '주의/관찰/양호'는 엔진의 층 확률을 말로 바꾼 표시다(1위 층 = 주의, 20% 이상 = 관찰, 그 밖 = 양호). 판단을 새로 하지 않는다.
* 색은 시안 2-4(밝은 초록 회색 바탕 + 초록 강조)로 바꿨다. `App.xaml` 토큰 **키 이름은 그대로**라 다른 창(`SymptomDialog`)도 같이 바뀐다.
  다크 모드는 나중에 버튼으로 바꾸게 할 예정이라 이번에는 밝은 화면만 만들었다(토큰 값만 바꿔 끼우면 된다).
* 증상 선택 창(`SymptomDialog`)의 글자는 손대지 않았다(참여자판과 맞추는 수정은 따로 한다).
* `--selftest`, `--open`, `--shot`, `--rehearse`, `--record-demo` 는 그대로 쓸 수 있다. `--record-demo` 는 블랙박스 기록 페이지의 [수집기 로그] 탭을 띄운다.

### 상담 도우미 에이전트

* 에이전트는 서버로 띄울 계획(2026-10-15)이라 클라이언트에는 연결 지점 `IChatAgent`(`Services/ChatAgent.cs`)만 두었다.
  지금은 Python 시안 `ce_agent.py` 의 오프라인 대역(`OfflineAgent`)을 C# 으로 옮긴 `OfflineChatAgent` 가 붙어 있다.
  ('그대로예요', '사라졌어요', '못 하겠어요', '왜요?', '적용했어요', '2시간 재발 없었어요' 같은 정해진 표현을 알아듣고 같은 엔진 도구를 부른다.)
* 서버 에이전트가 생기면 `IChatAgent` 를 구현한 클래스를 추가하고 `ChatAgentFactory.Create` 에서 고르면 된다. 화면 코드는 고치지 않아도 된다.

### 상담 도우미 그림 바꾸기

* 오른쪽 아래 버튼(약 52px)과 상담 창 머리(약 36px)의 그림은 `assets/chatbot.png` 하나를 쓴다. 지금 그림은 임시(초록 원 + 말풍선)다.
* **이 파일만 같은 이름으로 바꿔 넣고 다시 빌드하면** 그림이 바뀐다(빌드 때 실행 파일 옆 `assets` 로 복사된다). 코드는 고치지 않아도 된다.
  PNG, 정사각형, 128×128 정도를 권장하고, 배경을 투명하게 만들면 바탕색과 자연스럽게 이어진다.
* 찾는 순서: `CE_CHATBOT_IMAGE` 환경 변수 → 실행 파일 옆 `assets\chatbot.png` → 저장소의 `ui\wpf\CrashAnalyzer.UI\assets\chatbot.png`.
* 그림 파일이 없거나 읽지 못하면 글자 버튼(`상담 도우미 ▲`)으로 나온다.

### 2026-11-02 추가 — 실행 파일, 파이썬 시안 정리

* `ui\wpf\run_ui.bat`: 더블클릭하면 실행한다(처음이면 먼저 빌드). 인자를 그대로 넘기므로 `run_ui.bat --open engine\data\samples\s1_anticheat_crash.json` 처럼도 쓸 수 있다.
* `--open` 에 상대 경로를 주면 엔진이 파일을 못 찾던 문제를 고쳤다(전체 경로로 바꿔 넘김). 노트북 Windows 에서 빌드·실행을 확인했다.
* 기능이 다 옮겨져서 파이썬 시안(`ui/prototype-python`)은 폴더째 지웠다. 상담의 Claude API 연결(`ce_agent.py`)은 서버 에이전트로 다시 만들 예정이라 옮기지 않았다(저장소 기록에 남아 있음).
