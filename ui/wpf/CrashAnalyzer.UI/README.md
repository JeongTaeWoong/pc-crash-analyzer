# ui/wpf/CrashAnalyzer.UI — 최종 UI (C# WPF) v1

Python 시안(`ui/prototype-python`)의 C# WPF 포팅 + **수집기 상주 통합** 1단계 (2026-10-12 결정 사항 이행).
UI는 판단하지 않는다 — 층·확률·순서·실행 방식은 전부 엔진(`crash_engine tool ...`)의 응답을 그대로 보여 준다.

## 빌드·실행

```powershell
# 선행: 엔진 빌드(engine/README.md), 수집기 빌드(dotnet build collector/BlackBox -c Release)
dotnet build ui/wpf/CrashAnalyzer.UI -c Release
ui\wpf\CrashAnalyzer.UI\bin\Release\net8.0-windows\CrashAnalyzerUI.exe
```

- 엔진 위치는 자동 탐색(`engine/build/Release/crash_engine.exe`), 다르면 `CE_ENGINE` 환경 변수.
- 덤프 탐색 루트는 `collector/` 전체, 다르면 `CE_DUMPS`.
- `--selftest [출력파일]` : GUI 없이 엔진 연결·진단 매핑 검증 (스모크/CI용).
- `--open <스냅샷.json>` : 시작하자마자 해당 스냅샷을 진단 (시연용).
- `--shot <저장.png> [--open ...]` : 창을 화면 밖에서 렌더해 PNG로 저장 후 종료 — 사용자 화면을
  캡처하지 않는 자가 검수용.

### 2026-11-02 추가 — 상담 대역이 같은 답만 되풀이하던 문제

* 점검을 다 해도 원인을 못 찾은 상태(`exhausted`)에서 "아직 그대로예요"를 보내면 같은 상태 글만 계속 나왔다. 오프라인 대역(`OfflineChatAgent`)을 고쳤다.
  * `exhausted`: 해 본 점검 목록과 결과, 남은 후보, 할 수 있는 것(수집기를 켜고 다시 재현 → 새 기록으로 검진, 점검 범위 밖 후보 직접 확인, 증상 다시 고르기)을 안내한다.
  * `failed`: 써 본 해결책 목록과 다음에 해 볼 것을 안내한다.
  * "다른 방법은 없어요?": 점검 중이면 '할 수 없어요'로 넘기는 법, 원인 확인 뒤에는 준비된 해결책 전체(기대 해결률 순)를 보여 준다.
  * 상태가 그대로라 답이 똑같으면 긴 글을 반복하지 않고 짧게 알려 준다.
* 오프라인 대역은 정해진 표현만 이해한다. 자유로운 대화는 서버 에이전트(`IChatAgent`)를 연결한 뒤에 된다.

## 2026-11-02 추가 — PC블랙박스 연결 · 실행기(조치 실행 + 롤백)

### PC블랙박스 연결

* 새 기록 감시를 `Services/DumpWatcher.cs` 로 옮겼다. 아래 폴더에 `engine-snapshot.json` 이 새로 생기면, 누가 수집기를 켰든 자동으로 검진한다.
  `CE_DUMPS` → 저장소 `collector/` → `C:\ProgramData\PcBlackBox`(PC블랙박스 관리자 실행) → `%LOCALAPPDATA%\PcCrashAnalyzer`(PC블랙박스 비관리자 실행).
  [최근 기록 열기]도 이 폴더들을 모두 찾는다.
* PC블랙박스(트레이 앱 `PcBlackBox.exe`)가 켜져 있으면 머리글에 "PC블랙박스 수집 중"으로 보이고, UI 의 [수집 시작]은 막는다(수집기 두 개가 같은 문제를 두 번 기록하지 않게).
* PC블랙박스를 "자동으로 켜기"로 설치하면 PC 를 켤 때마다 수집이 시작되므로, UI 는 기록만 받아서 검진하면 된다.
* **확인 필요:** PC블랙박스 기록 폴더에 `engine-snapshot.json` 이 같이 생기는지(정태웅). 안 생기면 자동 검진이 되지 않는다.

### 실행기 (`Services/Executor/`)

중간발표 9~10번 슬라이드의 위험도 단계와 약속(실행 전 원복 지점 기록 · 악화되면 자동 원복 · 모든 조치 로그)을 코드로 옮겼다.
수집기는 읽기만 하는 원칙(collector `CLAUDE.md` 3번)이라, 바꾸는 일은 UI 쪽 실행기만 한다.

| 위험도 | 엔진 실행 방식 | 이번 버전 |
|---|---|---|
| Lv1 자동 실행 | `auto` | 자동 점검 모드에서 점검이 나오면 바로 실행 |
| Lv2 원클릭 동의 | `confirm` + 되돌릴 수 있음 | [동의하고 실행]을 누르면 실행 |
| Lv3 명시적 승인 | `confirm` + 되돌릴 수 없음 | 실행하지 않음 (다음 단계: 승인 + 시스템 복원 지점) |
| Lv4 직접 작업 | `manual` | 실행하지 않음 (단계 안내만) |

* 자동 실행하는 조치: `stop_process`, `stop_service`, `service_start_type`, `firewall_allow`, Microsoft Defender 의 `av_exclude`·`av_realtime`.
  오버레이 끄기·다른 회사 백신·제거·드라이버 롤백 등은 "지원하지 않음"으로 보여 주고 단계만 안내한다.
* 바꾸는 방법은 Windows 기본 도구만 쓴다: `sc.exe`, `netsh`, PowerShell Defender 명령, 레지스트리 읽기. 관리자 권한이 필요하다.
* **되돌리는 경우**: 실행 도중 실패 / 점검 결과가 '그대로'·'할 수 없어요' / 확인 중에 블랙박스가 새 오류를 기록 / 해결책 검증이 '재발' /
  [지금 되돌리기] / 실시간 보호 일시 중지 시간이 끝남 / 다음에 UI 를 켤 때 '실행 중·확인 중'으로 남은 기록이 있음(도중에 꺼짐).
* 기록 파일: `%LOCALAPPDATA%\PcCrashAnalyzer\executor\journal.json` (`CE_EXEC_JOURNAL` 로 바꿀 수 있음). 바꾸기 **전** 상태를 먼저 적고 바꾼다.
* **시험 실행(기본 켜짐)**: 상태는 실제로 읽지만 바꾸는 명령은 실행하지 않고 기록만 남긴다. 실행·확인·되돌리기 흐름이 화면에 그대로 보인다.
